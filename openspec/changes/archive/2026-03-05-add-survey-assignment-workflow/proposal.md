## 背景与动机

系统当前只有前端问卷演示页面，还没有完整的问卷业务闭环。我们需要上线可用于生产的能力：维护问卷模板、给用户分发问卷填写任务、收集作答并追踪完成进度。

## 变更内容

- 新增问卷模板管理，支持结构化题目定义（单选、多选、文本）。
- 新增模板发布能力，发布后生成不可变的模板版本。
- 新增问卷填写任务管理，可将某个模板版本分发给指定用户 ID 列表。
- 新增用户作答 API，支持在任务结束或截止时间前覆盖式重复提交。
- 新增任务进度与状态计算（`in_progress`、`completed`），在全员提交后自动完成。
- 新增管理员手动结束任务能力，可提前收集完毕。
- 新增结果查询 API，支持按用户明细与按题目聚合汇总。
- 针对原始答案访问新增权限校验与审计日志，降低隐私风险。
- 新增“测试先行”交付约束：业务实现前必须先完成 Gherkin 验收场景编写（BDD 先行）。
- 新增“TDD 先行”交付约束：实现前先对齐当前后端各层测试风格，新代码按既有测试风格以红-绿-重构方式开发。
- 新增验收自动化约束：接口层与 UI 层均通过同一份 feature 的 Behave `--stage` 自动化验收（UI stage step 内部使用 Playwright 驱动）。

## 能力拆分

### 新增能力
- `survey-template-management`：创建、更新、列表查询、发布问卷模板，并支持版本冻结。
- `survey-assignment-management`：基于已发布模板版本创建并管理问卷填写任务。
- `survey-submission-management`：允许被分发用户在截止与状态约束下提交和重复提交。
- `survey-progress-results-visibility`：提供任务进度、结果明细与结果汇总，并附带访问控制与审计。
- `engineering-quality-gates`：定义 BDD/TDD 与自动化验收的工程质量门禁，以及 feature 文件组织规范。

### 变更既有能力
- 无。

## 影响范围

- 后端：
  - 新增模板、模板版本、任务、参与人、提交记录等领域实体和值对象。
  - 在 `api/v1/surveys/*` 下新增应用层命令/查询和 HTTP 控制器。
  - 新增持久化模型与迁移，补充进度与汇总查询网关。
  - 新增结果访问授权策略与审计事件埋点。
- 前端：
  - 以生产版页面替换当前 survey demo，覆盖模板管理、任务管理、用户填写、进度看板、结果查看。
  - 接入生成的 API Client 与本地/开发环境 mock 处理。
- API：
  - 新增模板 CRUD/发布、任务 CRUD/关闭、我的提交查询与写入、提交明细与汇总查询接口。
- 测试：
  - 新增后端单测/集成/HTTP-stage 测试与前端集成测试，覆盖主流程和边界场景。
  - 将 BDD/TDD 与 E2E 自动化作为发布前质量闸门。
